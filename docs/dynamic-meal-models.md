# Ingredient-based meal models (1.20.1 Forge)

Survivor's Delight wraps the inventory baked models of TFC's wheat bread sandwich,
all five soups and all five salads. Model selection reads the actual stack's
`FoodHandler.Dynamic#getIngredients()` each time; changing the meal's contents
also changes its appearance. Empty/unconfigured meals use their original baked
model, including its transforms, render types and resource-pack overrides.

## Resource-pack format

Put one rule per file at **`assets/<namespace>/meal_models/<name>.json`**.
The namespace may belong to your resource pack or addon. The model value is a
normal model resource location, without `models/` or `.json`:

```json
{
  "priority": 100,
  "meal": {"item": "tfc:food/wheat_bread_sandwich"},
  "ingredients": [
    {"ingredient": {"tag": "forge:eggs"}, "min": 2}
  ],
  "exact": false,
  "model": "farmersdelight:item/egg_sandwich"
}
```

For your own model, use e.g. `my_pack:item/special_sandwich` and create
`assets/my_pack/models/item/special_sandwich.json`. It may have its own parents,
textures, display transforms and item overrides. Referenced models and their
dependencies are registered before model baking and texture atlas stitching.

`meal` and each `ingredient` use the normal Forge 1.20.1 Ingredient JSON format:
`{"item":"..."}`, `{"tag":"..."}`, an array of alternatives, or a registered
custom ingredient. Tag definitions remain item tags supplied by the server's
data packs; the model-selection rules themselves are client assets.

| Field | Meaning |
| --- | --- |
| `meal` | Required selector for the finished meal; only the 11 supported TFC items are wrapped. |
| `ingredients` | Required array of conditions; every condition must pass. An empty array imposes no conditions unless `exact` is true (then only empty contents match). |
| `ingredient` | Required selector within a condition. |
| `min` | Minimum matching ingredient quantity, default 1; 0 permits exclusion rules. |
| `max` | Maximum quantity, default 2147483647. Set `min: 0, max: 0` to exclude an ingredient. |
| `count_mode` | Per-condition `items` (default) sums stored component stack counts; `stacks` counts matching nonempty component entries. |
| `exact` | Default false. True also requires every nonempty component to match at least one condition's selector. |
| `priority` | Integer, default 0. Higher priority wins. Ties use the full rule resource location in ascending lexical order. |
| `model` | Required model resource location. |
| `enabled` | Default true. False disables this file; other fields can be omitted. |

Each condition counts independently. Overlapping selectors can count the same
component, and `exact` checks membership rather than allocating components to
separate conditions. Quantities come from the **stored ingredients**, not the
number of finished meals in the player's hand. TFC aggregates repeated sandwich
ingredients into stack counts, so one stored egg stack with Count 2 satisfies
`min: 2` in `items` mode. Soup and salad data may use separate component entries.

## Soup example

This applies to one soup variant; use an array in `meal` to cover several variants.

```json
{
  "meal": {"item": "tfc:food/vegetables_soup"},
  "ingredients": [
    {"ingredient": {"item": "tfc:food/pumpkin_chunks"}}
  ],
  "model": "farmersdelight:item/pumpkin_soup"
}
```

## Reloading and overrides

Press **F3+T**, enable/disable a resource pack, or change resource-pack order to
reload the rules and their model dependencies. The manager reads assets in
`ModelEvent.RegisterAdditional` on each model reload, before the bakery collects
materials. It then wraps the new baked models in `ModifyBakingResult`. This avoids
ordering races between independent reload listeners. Old baked models keep their
own immutable rule/model bindings until the model manager switches to the new set.

Each file is independently replaceable by a higher resource pack. Different files
are combined and sorted by explicit priority. To remove a built-in rule, override
its exact path, for example:

`assets/survivorsdelight/meal_models/egg_sandwich.json`

```json
{"enabled": false}
```

Malformed rules log the resource path and source pack and are skipped for that
reload. Missing model files log the owning rule and are excluded from selection,
so another valid rule or the meal's original model can be used. No per-stack
selection cache or server-side rule state is retained.

Built-in rules: egg/chicken/bacon sandwiches, mixed/fruit salads.
They are generated by `SDMealModelProvider`.
The former hardcoded overrides in the shipped wheat sandwich model are replaced
by these assets. The old item predicates remain registered for compatibility
with resource packs that explicitly use them.

Other bread sandwich types are unchanged. Food data, recipe output and nutritional
values are unaffected; this feature selects the client item model.
